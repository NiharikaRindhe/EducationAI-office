# EduAI — Core Logic

Plain-language notes on the rules the system follows. For *how to run* the app, see [README.md](README.md).

---

## 1. Academic year

- Indian school year: **April → March**. Written as `2026-27`.
- February 2027 is still `2026-27`. The year only turns in April.
- Same rule in two places, kept in sync: `currentAcademicYear()` in TypeScript and `current_academic_year()` in Postgres.

---

## 2. Classes and batches

Batch is derived from class automatically — nobody sets it by hand.

| Classes | Batch | Login method |
|---|---|---|
| 1–4 | 1 | 4-digit **PIN** |
| 5–8 | 2 | Email + password |
| 9–10 | 3 | Email + password |

Class 4 → 5 is the switchover point: PIN is cleared and a password is issued.

---

## 3. The session loop (year rollover)

Run once a year by the School Admin. One click moves the whole school forward.

### What happens to each class

| Class | What happens |
|---|---|
| 1 → 2, 2 → 3, … 9 → 10 | Moves up one class |
| 4 → 5 | Moves up **and** gets a password (PIN deleted). Printed slips are generated. |
| 10 | Passes out — account deactivated, all records kept |
| New Class 1 | Empty afterwards. Admin is prompted to admit the new intake. |

### Hold-backs

- Any student can be ticked to **repeat** their class instead of moving up.
- A held-back Class 4 student **keeps their PIN** (they're still in Class 4).
- A held-back Class 10 student **stays active** — they're repeating, not graduating.

### Sections

Section names don't always match between classes (Class 6 may have only A, Class 7 only B and C).

- If the same section name exists in the class above → it carries over silently.
- If it doesn't → the wizard **asks**, showing only those cases. Two choices:
  - Create that section in the class above, or
  - Move those students into an existing section.
- **Safety net:** after promotion, any class+section a student sits in that has no section record gets one created automatically. A student can never end up in a section that doesn't exist.

### What carries into the new year

| Thing | Carries? |
|---|---|
| Subject teacher assignments | Yes — same class + section slot |
| Class teachers | Yes |
| Timetable | Yes, copied as an editable starting point |
| Section structure | Yes |
| Announcements | **No** — closed, because they were written for the classes that just left |

The rule for staff: *the section slot stays, a new cohort moves into it.* Whoever taught Class 3-A Maths still teaches Class 3-A Maths.

### Safety rules

- **Runs once per year.** A second attempt is blocked with a clear message.
- **All or nothing.** Every roster change happens in one database transaction. If anything fails, nothing changed and you can retry.
- Passwords for the Class 4 cohort are issued *before* the transaction on purpose — they still log in by PIN until it commits, so a failed run leaves nobody locked out.

## 4. Enrollment history

One row per student per year, so the past stays readable after students move.

| Outcome | Meaning |
|---|---|
| `enrolled` | Currently in this class this year |
| `promoted` | Moved up at the end of this year |
| `held_back` | Repeated this year |
| `graduated` | Left after Class 10 |

Example — the same student across two years:

```
2026-27   Class 6   Section A   promoted     ← where they were
2027-28   Class 7   Section B   enrolled     ← where they went
```

---

## 5. What happens to student data

Nothing is deleted on rollover.

- **Kept forever:** exam marks, badges, streaks, game attempts, notes, chat history.
- **Naturally separated by class:** subject progress is stored per class, so Class 2 Maths stays a Class 2 record and Class 3 starts clean.
- **Class 10 leavers:** records fully retained, only the login is switched off. Downloadable as CSV before the rollover runs.

## 6. Question bank

### Where questions come from

| Source | Who can delete it |
|---|---|
| `ai` — generated by the AI | The school |
| `teacher` — written by a teacher | The school |
| `eduai` — shared global library | Nobody at school level |

- Teachers can filter by source ("written by") to review just the AI batch before an exam.
- A question already used in an exam **cannot** be deleted — it would gut a published paper. Clear message instead.

### AI generation

- Questions are generated **only from books actually uploaded and indexed** for that class and subject — never invented from thin air. Each batch shows its citation (book, page range, number of excerpts used).
- Generated questions are **drafts**. The teacher edits or discards them, then saves the ones they want.
- Drafts are held in the browser session, so navigating away mid-review doesn't lose the batch.
- A subject appears in the dropdown when it's allowed for that class **and** has indexed content.

---

## 7. Access rules

- Every query is scoped to the caller's school. Super Admin is the only cross-school role.
- Teachers see only the classes and sections they're assigned to.
- Deactivated accounts are refused at login, not just hidden in the UI.
- Students never *choose* their class — it's bound to the account. Class pickers on shared lab PCs are only for finding your own login.
